Texture Lab expose une seule table d’outils, utilisée de deux façons : l’objet window.BinksyAPI (toujours présent dans app.html) et, si le navigateur le permet, des outils WebMCP enregistrés automatiquement. Chaque outil appelle la même logique que l’interface : l’écran se met à jour et l’enregistrement automatique suit. Toutes les méthodes sont asynchrones, renvoient du JSON et, en cas d’erreur, rejettent avec { code, message }.

WebGL2 est obligatoire. En Chromium headless, lance le navigateur avec --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist.

01Ce que l’agent peut faire

15 outils, aussi listés par await BinksyAPI.describe() avec leurs schémas JSON :

  • texturelab_describe · BinksyAPI.describe() — Décrit Texture Lab (pile d'effets de texture sur une image ou une vidéo, export PNG/JPEG/vidéo) et liste ses outils avec leurs schémas JSON.
  • texturelab_get_state · BinksyAPI.getState() — État courant : média chargé (nom, type, taille ; le média n'est jamais enregistré), pile d'effets (du bas vers le haut, avec uid et réglages), sortie et taille exacte de l'export.
  • texturelab_importer · BinksyAPI.importer() — Importe l'image (PNG, JPEG, WebP, GIF, AVIF, SVG…) ou la vidéo (MP4, WebM, MOV) de l'utilisateur, ou un projet texture-lab-projet.json, comme un glisser-déposer.
  • texturelab_exporter · BinksyAPI.exporter() — Exporte en pleine résolution sans téléchargement forcé : png, jpg, video (MP4 WebCodecs, sinon WebM) ou project (texture-lab-projet.json).
  • texturelab_lister_effets · BinksyAPI.listerEffets() — Liste les 80 effets (id, nom, famille) ; avec details: true, leurs réglages (clé, libellé, type, min, max, défaut, options).
  • texturelab_lister_presets · BinksyAPI.listerPresets() — Liste les 20 préréglages intégrés et ceux enregistrés par l’utilisateur, avec leurs effets.
  • texturelab_appliquer_preset · BinksyAPI.appliquerPreset() — Applique un préréglage par son nom (ex. « VHS 1994 », « Game Boy ») : il REMPLACE la pile.
  • texturelab_ajouter_effet · BinksyAPI.ajouterEffet() — Ajoute un effet en haut de la pile (appliqué en dernier), avec des réglages optionnels.
  • texturelab_regler_effet · BinksyAPI.reglerEffet() — Règle une couche de la pile : réglages, visibilité, opacité (0–1), mode de fusion (Normal, Produit, Écran, Incrustation, Lumière tamisée, Addition, Différence, Couleur, Luminosité), ou réinitialisation.
  • texturelab_retirer_effet · BinksyAPI.retirerEffet() — Retire une couche de la pile.
  • texturelab_deplacer_effet · BinksyAPI.deplacerEffet() — Déplace une couche dans la pile : position 0 = en bas (appliquée en premier).
  • texturelab_animer_effet · BinksyAPI.animerEffet() — Anime un réglage numérique d'une couche en boucle parfaite (ou l'opacité avec param: "_mix"), ou coupe son animation.
  • texturelab_regler_sortie · BinksyAPI.reglerSortie() — Règle la sortie : cadrage (orig, 1:1, 4:5, 9:16, 16:9), résolution (orig, 2160, 1440, 1080, 720 = petit côté), format (png, jpg, video), qualité JPEG 0,5–1, durée vidéo (s), images/s (24, 25, 30, 60), source vidéo (inT, outT, loopSrc, audio), aperçu (fast, full).
  • texturelab_annuler · BinksyAPI.annuler() — Annule la dernière modification de la pile ou de la sortie (redo: true pour rétablir).
  • texturelab_reset · BinksyAPI.reset() — Vide la pile d'effets (comme « Tout retirer »).

Les couches sont listées du bas vers le haut (position 0 = appliquée en premier). Chaque couche a un uid à passer à reglerEffet, retirerEffet, deplacerEffet, animerEffet.

02Connexion A — agent dans le navigateur (WebMCP)

WebMCP est une proposition du W3C encore expérimentale : un agent intégré au navigateur appelle directement les outils d’une page. Pour l’essayer aujourd’hui (les noms peuvent encore changer d’une version à l’autre) :

  1. Utilise un Chrome récent (146 ou plus, souvent Canary ou Dev) et ouvre chrome://flags/#enable-webmcp-testing, passe le réglage WebMCP for testing sur Enabled, puis relance Chrome.
  2. Ouvre https://texture.binksdesign.com/app.html (ou http://localhost…/app.html en local : il faut HTTPS ou localhost).
  3. Les outils texturelab_… apparaissent tout seuls pour l’agent du navigateur. Pour les voir et les tester à la main, l’extension Chrome Model Context Tool Inspector (proposée par la doc Chrome) les liste et les exécute.

L’app gère document.modelContext.registerTool() (spécification actuelle) et les anciennes préversions (navigator.modelContext, provideContext). Sans WebMCP, rien ne s’affiche et rien ne casse : window.BinksyAPI reste disponible.

03Connexion B — Claude Code, Codex, Hermes, OpenCode

Ces agents pilotent un navigateur local par un serveur MCP standard. Le plus simple : Playwright MCP. Ajoute-le à la configuration MCP de ton agent (fichier .mcp.json de Claude Code, configuration MCP de Codex, Hermes ou OpenCode — même bloc, la syntaxe du fichier peut varier) :

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

Puis demande à l’agent d’ouvrir l’app (browser_navigate vers https://texture.binksdesign.com/app.html) et d’appeler window.BinksyAPI avec l’outil d’évaluation de JavaScript (browser_evaluate), par exemple :

() => BinksyAPI.describe()

Pour un fichier de l’utilisateur, l’agent le lit sur le disque, l’encode en base64 et le passe à BinksyAPI.importer({ files: [{ name, type, dataBase64 }] }). Les fichiers exportés reviennent en base64 : l’agent les réécrit sur le disque. Importe toujours le fichier de l’utilisateur avant d’ajouter des effets : sans média, l’API refuse (l’interface chargerait l’image d’exemple).

04Exemples de code

Découvrir l’app et la liste des effets

await BinksyAPI.ready();
const info = await BinksyAPI.describe();
const { effects } = await BinksyAPI.listerEffets({ cat: 'trame', details: true });   // id, nom, réglages
const { presets } = await BinksyAPI.listerPresets();   // VHS 1994, Game Boy, Riso zine…

Importer une image en base64 et construire la pile

await BinksyAPI.importer({ files: [{ name: 'photo.jpg', type: 'image/jpeg', dataBase64: b64 }] });
await BinksyAPI.appliquerPreset({ name: 'VHS 1994' });            // remplace la pile
const { layer } = await BinksyAPI.ajouterEffet({ id: 'grain', params: { amount: 0.3 } });
await BinksyAPI.reglerEffet({ uid: layer.uid, opacity: 0.8, blend: 'Écran' });

Exporter (rien n’est téléchargé sauf download: true)

await BinksyAPI.reglerSortie({ aspect: '4:5', res: '1080' });
const { files } = await BinksyAPI.exporter({ format: 'jpg' });   // png, jpg, video ou project
files[0].name;   // photo-texturelab.jpg  (+ width, height, dataBase64)

05Prompt prêt à copier

À coller tel quel dans Claude Code, Codex, Hermes ou OpenCode (avec Playwright MCP branché) :

Ouvre https://texture.binksdesign.com/app.html avec le navigateur (Playwright MCP, Chromium avec WebGL2), attends que la page soit chargée, puis utilise uniquement window.BinksyAPI via browser_evaluate. Commence par await BinksyAPI.describe(). Importe ma photo ./photo.jpg (lis-la sur le disque, encode-la en base64, BinksyAPI.importer) avant tout effet. Applique le préréglage « VHS 1994 », règle la sortie en 4:5, puis exporte en JPEG (BinksyAPI.exporter({ format: 'jpg' })), décode le base64 et enregistre le fichier à côté de l’original. Exporte aussi le projet (format: 'project') pour que je puisse le rouvrir. N’utilise jamais l’image d’exemple et n’ajoute ni texte ni visuel de marque.

06Rien n’est envoyé

  • Rien n’est envoyé : l’image ou la vidéo est traitée dans le navigateur (WebGL2). Le média importé, la pile d’effets et la sortie sont gardés dans le navigateur (IndexedDB et localStorage) et reviennent au rechargement.
  • Pas de compte, pas de clé API : l’API ne lit ni n’écrit aucune clé.
  • L’API manipule seulement ce que l’utilisateur fournit : elle n’invente ni logo, ni couleur, ni nom de client.
  • Mode d’emploi complet pour agents : AGENTS.md · page Agents IA · llms.txt.

English, short version. Texture Lab exposes one tool table two ways: the always-present window.BinksyAPI object in app.html and, when the browser supports it, auto-registered WebMCP tools. Every call runs the same logic as the UI (screen and auto-save follow), returns JSON and rejects with { code, message }.

02Connecting an agent

  • WebMCP (browser agent): recent Chrome (146+), enable chrome://flags/#enable-webmcp-testing, relaunch, open https://texture.binksdesign.com/app.html; the texturelab_… tools show up automatically (inspect them with the Model Context Tool Inspector extension). Experimental: names may change.
  • Claude Code, Codex, Hermes, OpenCode: add Playwright MCP (npx @playwright/mcp@latest, config block above), open the app URL, then call window.BinksyAPI through browser_evaluate. Files go in and out as base64.
  • Nothing is sent: the image or video is processed in the browser (WebGL2). The imported media, the effect stack and output settings are kept in the browser (IndexedDB and localStorage) and come back on reload. No account, no API key.

03Ready-to-paste prompt

Open https://texture.binksdesign.com/app.html in the browser (Playwright MCP, Chromium with WebGL2), wait for the page to load, then use only window.BinksyAPI through browser_evaluate. Start with await BinksyAPI.describe(). Import my photo ./photo.jpg (read it from disk, base64-encode it, BinksyAPI.importer) before any effect. Apply the “VHS 1994” preset, set the output to 4:5, export as JPEG (BinksyAPI.exporter({ format: 'jpg' })), decode the base64 and save the file next to the original. Also export the project (format: 'project'). Never use the example image and add no brand text or visuals.
